## 后续工作与完成条件

以下均为计划，尚未交付；按真实需求安排，不承诺未经验证的完成日期。

| 优先级 | 计划 | 完成条件 |
| --- | --- | --- |
| P1 | 开展一个真实的独立应用集成试点 | 使用注册表依赖，不用本地 workspace/path 替换；保留可分享的集成源码、实际输入、尺寸编辑和失败处理流程、运行命令及结果。若仍由维护者开发，明确标为自建集成，不称第三方采用 |
| P1 | 收集与处理实际使用反馈 | 获得可公开的最小复现、版本、后端、预期与实际结果；记录复现、修复或暂不支持的结论，修复需有针对性回归。引用外部应用或反馈前获得公开授权 |
| P2 | 复核代表性模型的性能边界 | 在记录的机器、工具链、构型、初值和预算下报告迭代、QR 次数、残差和耗时；与旧版本同环境比较，不复用历史计时声称新版本更快 |
| P2 | 根据实际报告扩展环境覆盖 | 明确环境后先做最小复现；只有实际通过对应平台检查才增加支持证据，不把后端覆盖等同于所有操作系统验证 |

当前优先维护小型 Point / Line / Circle 草图及既有关系。圆弧、三维、文件交换或更多几何类型需由实际使用需求驱动，不因参赛规模要求随意扩张范围。能力边界见 [LIMITATIONS](LIMITATIONS.md)。

## 提交可复现反馈

普通问题通过仓库 [Issues](https://github.com/mik1e80/moonbit-cad-sketch/issues)反馈，可使用下列信息结构：

- 模块版本、操作系统、`moon version --all` 输出及目标后端。
- 不含个人信息或商业图纸的最小 MoonBit 示例；写明参数、初值、容差和计算预算。
- 执行命令、预期行为、实际状态、残差或错误；说明调用的是 checked API 还是旧便利接口。
- 若能公开，提供集成仓库与对应提交；不能公开时构造可授权的最小替代数据，不上传敏感资料。
- 修复后记录回归范围与结果；未复现、超出能力边界或暂不支持应如实说明。

安全问题按 [SECURITY](../SECURITY.md) 私密报告，不在公开问题中提交可利用细节。本页不会自动向任何用户发送邀请或创建未发生的问题记录。

## 维护与发布约定

- 日常只执行受影响的轻量检查；完整回归和大量模型实验单独明确安排。
- 每次修复先保留可复现输入及回归，接口变化通过 `moon info` 检查并在 CHANGELOG 说明；贡献要求见 [CONTRIBUTING](../CONTRIBUTING.md)。
- 已发布包与 tag 保持不变；实现变更另发新版本。发布前确认检查范围，发布后用仓库外项目验证注册表安装并保存归档指纹。
- 对本期成果、历史验证和后续计划分别标注日期、源码或版本；只记录真实完成的工作，不保证响应期限或评选结果。
