# 项目维护检查

按需执行以下检查，并在提交、发布收据或维护记录里附上范围与结果。适用条目随改动选择。

| 检查对象 | 验收证据 |
| --- | --- |
| 文档与接口 | 核对 README、快速开始、公开接口、变更记录及安装版本。可执行示例和受改动影响的文档链接可复现 |
| 发布与 Git | 从受保护的主分支开分支，提交集中在实际改动。PR 附测试范围、兼容性影响和许可证变化。正式包保存不可变版本、源码 SHA、归档指纹、完整回归和仓库外安装收据 |
| 输入与资源 | 检查非有限数、错误句柄、引用保护和对象上限。按改动检查求解、诊断和 SVG 边界，给出宿主的时间、内存和并发职责 |
| 状态与结果 | 检查失败不写回、旧快照隔离、ID 不复用、禁用关系的引用及预算终止。诊断样本记录子集尝试和实际停止原因 |
| 兼容性 | 记录平台、精确工具链、目标后端和通过的测试。维护探测与正式发布回归分开记录 |
| 性能 | 保存固定构型、初值、预算及样本。不同机器、工具链和构型的数字分别报告 |
| 许可与模型 | 核对 Apache-2.0 正文、依赖及实际用法。自建模型保留种子和解析期望，外部模型在入库前记录来源、许可和再分发权。安全报告走私密渠道 |

本轮维护证据见 [验证记录](MAINTENANCE.md)、[性能报告](BENCHMARK.md#041-维护基准)及[兼容性矩阵](COMPATIBILITY.md)。版权署名沿用项目已有决定，待权利人明确后再调整。

## 本轮计划逐项复核

以 0.4.1 发布记录和维护后的主分支为准。表中保留各验收对象的实际测试范围。

| 原计划 | 已交付的证据 |
| --- | --- |
| 稳定基线与开发方向 | [路线图](ROADMAP.md)、[功能矩阵](FEATURE_MATRIX.md)和[限制](LIMITATIONS.md)以小型二维草图及 37 种用户约束为范围。GitHub 简介与 0.4.1 功能一致 |
| 独立应用与反馈流程 | [圆角安装板](REGISTRY_PLATE.md)从发布注册表运行，已验证尺寸编辑、只读测量、冲突保留及恢复。仓库有缺陷和集成 Issue 表单、计划内八类标签、私密漏洞报告和维护里程碑。第三方使用与反馈需外部证据，排除在本轮完成项之外 |
| 随机与生命周期 | [维护记录](MAINTENANCE.md)保存固定种子、解析几何、连续编辑、句柄引用、编号不复用、checked 调用失败不写入和快照隔离的证据 |
| 圆弧 | 已覆盖两个方向、极小和极大尺寸、半圆两侧、零与整圆邻域、共享端点相切、有限投影切换及删除保护，见 [圆弧规格](ARC_DESIGN.md)与专项测试 |
| 诊断和输入资源 | 已覆盖重复固定与距离、独立冲突组、可恢复奇异初值、局部秩阈值、预算耗尽和非写回，见 [诊断边界](DIAGNOSTIC_DESIGN.md)、[限制](LIMITATIONS.md) |
| 性能与兼容性 | 七类工作负载已有实测，并在同一机器和工具链对照两个发布标签。[性能报告](BENCHMARK.md)和[兼容性](COMPATIBILITY.md)分别说明测量与平台范围 |
| 文档、许可与模型 | README、快速开始、几何及诊断规格与版本证据相互链接。复核了 50 份 Markdown 的仓库内链接和标题定位，未发现断链。Apache-2.0、第三方参考范围、生成数据清单与再分发规则分别记录，见 [模型政策](MODEL_DATA_POLICY.md)及[第三方说明](../THIRD_PARTY_NOTICES.md) |
| GitHub 与 CI | 已核对 main 的四项必需检查与禁止强推、删除设置。默认轻量、手动完整回归、兼容性及维护检查按各自场景执行 |
| 正式发布验收 | [0.4.1 维护后验收收据](releases/0.4.1-maintenance-acceptance.json)绑定 GitHub tag、维护源码 SHA、完整回归、源码归档和空缓存注册表下载。稳定运行时保持在 0.4.1 |

以上已交付的检查、工作流及文档可以在以后按需复用。新功能评估、后续稳定工具链复测和新版本验收各自随实际改动触发。
